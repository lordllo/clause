# Online demo deployment

The root `Dockerfile` builds the existing Next.js frontend as static assets and serves them alongside FastAPI. Browser requests use `/api` on the same HTTPS origin. The two-process local development workflow remains supported.

## Render

Connect your Render account and grant it access to the private GitHub repository `lordllo/clause`. Create a Blueprint from the repository; `render.yaml` defines a free web service with a generated session-signing secret and a health check at `/api/health`. No LLM API key is needed. A Render connection is required before the agent can provision and publish the service.

This first deployment intentionally uses an ephemeral SQLite demo database. It reseeds the 73 bundled samples on restart. Visitor uploads, policies and reviews are isolated by a signed HttpOnly browser cookie and expire after one hour. Cleanup runs opportunistically on API requests, at most once per minute; expired session identities cannot reopen old uploads even before cleanup. Restarting a free instance can remove visitor state earlier. The demo is for public and fictional documents only.

Do not claim durable visitor storage for this free deployment. Persistent customer workspaces require a funded hosting plan, authentication, hosted Postgres, object storage and a retention policy. The data model still supports Postgres and pgvector; a provider-style `postgresql://` URL is normalized to the psycopg driver. These enterprise capabilities are not provisioned by the free blueprint.

## Environment

| Variable | Hosted value |
|---|---|
| `PUBLIC_DEMO` | `true` |
| `ANALYSIS_PROVIDER` | `demo` (other providers rejected in public mode) |
| `DEMO_SESSION_SECRET` | Random secret, at least 32 characters; generated by Render |
| `DEMO_COOKIE_SECURE` | `true` behind HTTPS |
| `DEMO_SEED` | `true` |
| `STATIC_DIR` | `/app/web` (set by Dockerfile) |
| `DATA_DIR` | `/app/backend/data` (set by Dockerfile) |
| `PORT` | Assigned by host |

The demo permits five uploads per browser session and limits writes to 20 per minute per client address/session pair. Request bodies are bounded and cross-origin writes are rejected. Limits are per process and are not a distributed abuse-prevention service. Run one API worker. Use provider-level request/IP controls before any high-traffic launch. Parsing is bounded but not sandboxed.

## Local hosting smoke test

```sh
cd frontend
CLAUSE_STATIC_EXPORT=true NEXT_PUBLIC_API_URL=/api npm run build
cd ../backend
PUBLIC_DEMO=true DEMO_SESSION_SECRET=replace-with-a-long-random-secret DEMO_COOKIE_SECURE=false STATIC_DIR=../frontend/out python -m uvicorn app.main:hosted --host 127.0.0.1 --port 8001
```

On PowerShell, set those environment variables using `$env:NAME='value'` before each command. Open http://localhost:8001. The secure-cookie exception is strictly for this local HTTP smoke test. Never use it for the HTTPS deployment.

Verify health and all 73 samples; open a guided review; search and inspect a CUAD annotation; upload a fictional agreement; verify that a second browser session cannot access the first session's upload, policy, or review. Automated tests cover that isolation, expiry, forged cookies, cross-origin writes, quotas, and rejection of paid LLM mode.
